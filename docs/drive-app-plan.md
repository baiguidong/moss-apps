# Moss 网盘 App 第一版开发计划

第一版围绕“找到文件、上传文件、下载文件”三个动作完成闭环。页面采用单一文件列表工作区，配合可展开的传输面板，沿用 Moss 的颜色、控件与间距风格。

应用名称为“网盘”，目录为 `apps/drive/`，App ID 为 `moss.drive`，初始版本为 `0.1.0`。使用当前 Moss 远程账号的个人云端空间，复用已有登录和存储配置。

本计划已落地为 `apps/drive/`，当前版本为 `0.2.0`：

- 顶部为“全部文件／上传／下载”三个标签，切换保留路径，任务完成不自动跳转。
- 全部文件支持根目录及子目录的新建目录，校验名称并说明同名冲突。
- 文件行提供删除确认，成功后更新列表和容量；失败、权限不足时保持文件并显示原因。
- Backend 增加 `folders.create`、`files.delete`，申请 `cloud-storage:delete`，继续直接引用 Core SDK。

下方保留 0.1.0 的原始范围与设计示意。当前使用说明见 [网盘 README](../apps/drive/README.md)，实际验收范围见 [验证记录](drive-app-verification.md)。

第一版的功能范围：

| 功能 | 交互与结果 |
| --- | --- |
| 文件列表 | 展示文件和文件夹；文件名、大小、修改时间和操作四列；支持刷新和按游标加载更多 |
| 目录浏览 | 点击文件夹进入，通过面包屑返回上级或根目录 |
| 上传 | 点击“上传文件”，在系统选择器中选择一个或多个文件，上传到发起操作时所在的目录 |
| 下载 | 点击文件行的“下载”，在系统对话框中选择保存位置 |
| 传输状态 | 查看每个任务的进度、状态与错误，支持暂停、继续和取消；重新打开页面后恢复任务展示 |

分享、预览、删除、重命名、新建文件夹、回收站、自动同步、全文搜索、拖拽上传和批量下载留到后续版本。首版上传入口使用现有受控文件选择能力。

├────────────────────────────────────────────────────────────┤
│ 名称                           大小       修改时间    操作 │
│ 文件夹 设计稿                  —          09-24             │
│ 文档   项目说明.pdf            2.4 MB     09-24        下载 │
│ 图片   页面截图.png            860 KB     09-23        下载 │
│                                                            │
│                        加载更多                            │
├────────────────────────────────────────────────────────────┤
│ 已加载 36 项                         已用容量 / 总容量     │

┌────────────────────────────────────────────────────────────┐

视觉上以紧凑工具栏、细边框、适度留白和清晰文字层级组织内容。绿色强调“上传文件”，刷新、传输及逐行下载使用较轻的按钮样式；文件夹与文件使用统一的线性图标。容量只占底部一行辅助信息。

列表是页面主要滚动区域。传输面板展开时限制高度并独立滚动，保留文件浏览空间；用户发起上传或下载后展示任务摘要，已有任务通过顶栏入口查看。下载入口在键盘聚焦和触屏操作时同样可用。窄窗口保留文件名与操作，将大小和时间收进名称下方的次级信息。

Moss 外观、主题同步、可访问性和启动兜底按创建规范自动实现，不增加单独的外观设置页。具体实现以 Core 的 App 创建规范为准，只借鉴现有 App 的适用组件，避免复制整套 OpenIM 界面与样式。

交互约定：

- 首次打开先确认服务状态。就绪后加载根目录和传输任务；空目录显示“还没有文件”和上传入口。
- 上传的目标目录在点击上传时确定，选择文件期间切换目录也不会改变目标。每个文件独立创建任务，部分文件失败不影响已经创建的任务，不自动重提整批上传。
- 文件选择器或保存对话框被用户取消时正常返回页面。下载任务仅适用于文件，文件夹只提供进入操作。
- 创建任务成功后显示传输中，收到完成状态后才显示完成。上传完成时刷新当前目录；刷新采用请求序号和节流，旧请求不能覆盖新目录。
- 同名上传提示冲突，不自动覆盖；下载目标已存在时提示另选位置。失败项保留文件名与可理解的错误信息。
- 暂停、恢复和取消按钮随任务状态变化。取消结果尚未确认时显示“正在取消”，以 Host 的最终状态为准；完成与取消并发时可以最终显示已完成。
- 页面关闭后 Host 可继续传输。退出 Moss 后未完成任务暂停，下次打开由用户点击继续；失败导致的暂停同时显示错误原因。
- 服务未配置、未登录、连接失败、容量不足或权限不足时，展示简短说明和适用的重试操作。配置提示引导用户在 Moss 设置中连接服务器，不臆造跳转设置的 API。
- 远程账号或连接发生变化时清空旧目录与文件展示，作废旧请求，再从当前账号根目录重新加载。目录和文件元数据不跨账号保存在 App KV。
- 普通浏览器预览提供明确标注的演示数据，真实运行不将演示任务与真实任务混用。

实现采用 Vite、React 和 TypeScript，配一个 `persistent` Node Backend。Backend 只负责受控请求、输入/输出校验和事件转发，文件内容、分片、续传与下载落盘全部交给 Moss Host。SDK 通过现有 Core 子模块 workspace 引用。

Manifest 使用 Schema V2、`hostApi: ^2.2.0` 和 `moss.cloud-storage/v1`，仅申请 `cloud-storage:read`、`cloud-storage:write`。每个 App 一个 Backend、一个页面入口，按当前仓库约定维护 publisher、marketplace、图标、Schema、版本和构建脚本。

| App Backend action | Host 方法 | 用途 |
| --- | --- | --- |
| `status.get` | `status.get` | 云端服务状态 |
| `quota.get` | `quota.get` | 底部容量信息 |
| `files.list` | `files.list` | 根目录、子目录与分页 |
| `local-files.pick` | `local-files.pick` | 系统选择器返回受控文件句柄 |
| `uploads.start` | `uploads.start` | 按文件创建上传任务，携带目标目录 |
| `downloads.start` | `downloads.start` | 选择保存位置并创建下载任务 |
| `transfers.list` | `transfers.list` | 初始加载和重新打开时恢复任务展示 |
| `transfers.get` | `transfers.get` | 单个任务状态校准 |
| `transfers.pause/resume/cancel` | 同名方法 | 传输控制 |

仅暴露上述明确声明的 action，不提供任意协议转发。Backend 将 `transfers.progress`、`transfers.changed`、`storage.status-changed` 转发给 UI。UI 按任务 ID 合并事件，订阅与卸载配对；重新打开页面时用分页任务查询恢复状态，事件与查询返回的数据按 `updatedAt` 合并，避免旧快照覆盖新进度。

文件和任务列表均按 Host 游标分页，单页不超过 200 项。文件接口没有总数和全局搜索/排序参数，页面使用“已加载 N 项”和“加载更多”，不展示推算的总数。任务列表按需加载历史任务；获取当前任务摘要时遍历任务分页，不将首屏历史任务当成全部传输。

开发按以下顺序推进：

1. **页面与工程骨架。** 建立 `apps/drive/`、Manifest、构建脚本和基础组件，用演示数据实现文件列表、空目录及展开的传输面板，形成可检查的页面预览。
2. **真实文件链路。** 接入状态、目录分页、多文件上传和单文件下载，校验任务创建、部分失败、目录切换和同名冲突处理。
3. **传输与恢复。** 接入进度事件、暂停/继续/取消、重新打开后的任务恢复，以及账号变化与连接中断处理。
4. **验证与交付。** 完成针对性测试、类型检查、构建和 ZIP 打包，在 Moss Desktop 上走通真实上传下载并检查页面效果。产出可安装的 `moss.drive@0.1.0` 包及 README。

验收以真实操作结果为准：

- 可在根目录和已有子目录间往返，分页无重复，旧请求不串入新目录。
- 多文件上传能分别显示结果，任务完成后重新打开 App 仍可看到文件。
- 下载文件内容与原文件一致；取消保存对话框不产生虚假失败任务。
- 传输进度、暂停、继续及取消与真实任务对应；部分失败不显示整批成功。
- 页面重开可恢复任务展示；Moss 重启后暂停任务能由用户显式恢复。
- 切换账号不会残留上一账号的文件、目录或任务。
- 空目录、连接不可用、权限不足、同名冲突及容量不足都有可理解的处理。
- 浅色、深色及窄窗口下布局和操作清晰；首次加载或脚本失败仍有可见内容。
- 本仓库 `validate`、`check`、`test`、`build` 与本地打包通过。真实服务验证需使用已登录且启用云端存储的 Moss Desktop/Server 环境；演示数据和单元测试不代替该验证。
