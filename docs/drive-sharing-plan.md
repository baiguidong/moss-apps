# 网盘文件分享实施方案

本轮实现 Core Server、Desktop Host、SDK 与网盘 App 的单文件只读分享。

## 用户操作

- 文件行增加“分享”。弹窗选择 1 天、7 天（默认）、30 天、自定义到期时间或永久；默认自动生成 6 位分享码，可关闭或修改为 4–12 位字母数字。
- 创建后显示链接、分享码与到期时间，分别提供“复制链接”和“复制分享信息”。创建请求携带幂等键，超时重试不会重复创建。
- 顶部增加“已分享”：文件名、大小、创建时间、到期时间、分享码、状态和操作。按创建时间倒序分页，保留已过期、已取消、文件失效记录。支持复制和确认取消分享。
- 同一文件可创建多个独立分享。每条分享绑定文件 ID 与内容版本；改名或移动保持可用，删除或内容版本变化使分享失效。取消分享不删除原文件。
- 接收者无需 Moss 账号。无分享码链接打开即下载；有分享码先展示验证页，再使用短期、HttpOnly、限定路径的会话下载。错误码、过期和撤销都给出可读页面。

## Core

- SQLite/MySQL 增加分享表与升级迁移，保存所有权、文件版本、到期和撤销时间、幂等键。分享凭证/分享码加密保存，分享码另存校验哈希，只有所有者的管理接口返回可复制的信息。
- Server 增加登录态分享管理 API 和专用公开 `/s/:token` 访问入口。已有普通文件 API 保持原鉴权。公开链接优先使用配置 `server.publicUrl`，未配置时 Host 使用当前连接地址。
- 所有下载（包括 HEAD/Range）检查分享有效性、文件版本、所有者状态；活动流定期重检，复用存储流与并发限制。提取码验证限制尝试次数，分享页面和响应禁用缓存及 referrer。
- SDK/Host 增加 `shares.create/list/revoke` 和独立 `cloud-storage:share` 权限，Host API 升级为 2.3。网盘更新到 0.3.0；分享接口不可用时保留文件与传输功能并明确提示升级/授权。
- 浏览器页面由 Server 托管，桌面退出不影响分享。分享时间由 Server 判定；数据库与凭据主密钥共同备份。

## 接入与验证

1. 完成持久化、授权、加密、管理与公开下载接口。
2. 完成 SDK 契约、Host 转发、权限和兼容处理。
3. 完成分享弹窗、“已分享”分页列表与浏览器演示。账号切换清空分享数据并丢弃旧请求。
4. 验证跨用户/跨组织隔离、幂等、正确/错误分享码、过期、撤销、删除、重启恢复、Range/HEAD 及活动流中止；运行 Core 与 App 针对性回归、类型检查、构建及浏览器界面测试。

Core 工作区已有其他未提交修改，本轮仅修改分享所需文件。SDK 继续由 Core 维护；消费端通过子模块引用 Core 的分享实现，不维护 SDK 副本。
