# Knowledge RAG App 实施规划

日期：2026-10-12。流程：规划 → 规划 review → 开发 → review → 修复 → 汇总。

## 目标与范围

新增独立 `moss.knowledge-rag@0.1.0`，与 `moss.library` 并存。默认 `toolScope: session`，用户通过会话 App 选择使用，不增加全局默认知识库选择器、不迁移现有资料。用户已确认本轮同时提供 App 内 session/global 切换。Host 保存用户级、App 级覆盖，Manifest 仅提供默认值；切换统一影响原生和 MCP 工具，忙碌会话下一轮生效。

首版提供中文界面：引擎准备及状态、资料浏览、搜索、正文阅读、本地文件导入、索引进度、重新索引、连接信息。原生 MCP 工具通过现有 Host 发现和调用，页面使用明确的 Backend Actions。保留上游 13 个工具契约，不静态重复注册一套 AI 工具。

## 架构

- App persistent Node Backend 托管一个本地 knowledge-rag HTTP MCP 服务，绑定 127.0.0.1，使用随机 Bearer token。会话与页面共享该进程，禁止以各会话 stdio 启动同一索引。
- App 私有目录保存文档副本、独立 Python 环境、模型缓存、索引和设置；不读取用户现有知识库资料、不改原文件。包内固定 knowledge-rag 版本及依赖锁，首次明确准备引擎时安装到私有环境，之后重启复用。
- Python 使用 Moss 受管运行时；开发和对比脚本可明确传测试 Python。模型默认采用适合中文且相对轻量的 multilingual-e5-small，正确设置 query/passage 前缀；首版关闭默认英文重排器。记录模型与依赖版本。
- App 通过 `moss.mcp/v1` 注册 HTTP 服务，env/headers 由 Host 凭据存储管理。页面通过 Backend 内 MCP client 请求固定工具；不向页面暴露 token。
- 关闭页面不停止服务；停用 App 或退出 Backend 关闭子进程。准备/启动不能阻塞 SDK 握手。操作有超时、取消、错误状态和重试，不因轮询重复启动进程。
- 导入仅支持明确选择的普通文件，复制到受管文档目录，限制大小并拒绝符号链接；同源重导入确定性更新，重名异源不互相覆盖。索引完成状态以实际 reindex 结果为准。
- 上游原始 source filepath 不伪装成 Moss URI。首版通过页面读取来源并提供索引内相对路径；完整历史引用协议留作后续增强并明确限制。

## 验证与对比

1. 单元与集成：输入/路径校验、工具错误解码、取消、单实例与重启、准备失败重试、分页适配、MCP 注册及会话范围。
2. 实际引擎：真实 CPU embedding 和 ChromaDB，使用独立测试目录，验证导入、检索、阅读、重建、两个 HTTP 客户端及重启持久化。
3. UI：真实 Backend/Host 集成，浅色/深色和小窗口截图，无 renderer 错误；可重复运行的测试脚本与证据。
4. 同语料对比：固定公开合成业务文档，冻结查询与期望来源后再运行。覆盖中文精确词、自然问法、同义表述、中英跨语言、代码标识符、多资料证据和无答案问题。不使用私人资料，不根据结果删除失败样本。
5. 记录 Recall@5、MRR@5、证据覆盖、逐题 top hits、实际返回片段、冷/热时延和可测的资源开销；两边使用相同 top-k、原文和问题。分别报告检索效果与 UI 效果，不把模型生成答案当检索事实。
6. 构建、Manifest 校验、包含源码的独立安装包及隔离 Runtime 安装验证。不发布 GitHub/市场、不替换现有 App 安装。

## 规划 review（开发前）

结论：按以下修订实施。

1. **多会话并发：** 原始 stdio 方案会重复启动写入进程，已改为 Backend 持有单实例 HTTP 服务，健康检查与实际 MCP 握手均通过后才注册为可用。
2. **中文公平性：** 不将上游英文默认配置直接作为唯一候选；主比较采用明确记录的多语言模型、关闭英文重排器。报告区分“当前 App”与“适配后的 knowledge-rag”，不声称是原厂默认效果。
3. **握手与安装：** 初次依赖/模型下载可能很慢，必须后台执行并提供状态；任何缺少 Python、下载失败或启动失败都保持页面可用。
4. **工具范围：** 不通过修改签名 Manifest 或仅变 UI 文案实现动态 scope。若本轮要求切换，先补 Host 持久化和全部原生/MCP 工具策略，再加 App 设置。
5. **文档模型：** 上游分类不等于现有资料集。首版直接显示文件夹/分类和路径，避免伪造资料集 CRUD；上游不提供列表分页，页面 Backend 本地切页并在说明中注明全量读取成本。
6. **性能口径：** embedding 模型预热与冷启动分开；小样本评估只说明该语料结果，保留无命中及误召回。评测不依赖外部 LLM，不虚构回答质量。
7. **交付风险：** 当前磁盘约 9 GiB 可用，优先小型多语言模型，模型不进 ZIP；避免复制大环境。验证在临时数据和专用 artifacts 内，不触及现有用户数据。
