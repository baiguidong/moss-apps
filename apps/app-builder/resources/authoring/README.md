Tool visibility is declared once at the root of app.moss.json: toolScope is session (default) or global. Every native contribution and every App-owned MCP service inherits it. New projects and Skill conversions choose explicitly by intended use: general helpers available in every conversation once enabled, such as Sequential Thinking, use global; Apps requiring conversation selection use session. Keep session when cross-conversation use is not required. Neither a missing UI, navigation placement nor a persistent Backend implies global. Preserve scope in ordinary edits; an absent field means session on Host 3.1+. The adjacent app.moss.json is a minimal session template; replace its scope when the intended use requires global.

Session Apps expose tools only after the user selects the App using @, the resource picker, or one of its resources; selection persists through conversation restore until removal. Validate the emitted manifest and packaged/restored source with the same SDK, then verify actual native/MCP visibility in selected and unselected sessions.

## Independent App subservices

Use root `toolSelection: "services"` only when users need to choose individual services. This requires Host API >=3.8.0 and a matching pinned SDK. Otherwise retain the default `app` selection mode. For native tools declare `contributes.services: [{id,title,description?}]` and put a valid `serviceId` on every tool; MCP registrations provide dynamic children automatically for any declaring App. Native and MCP children may coexist. Preserve stable IDs and selection mode during edits and source restore. Never infer child mode from the number of transports.

Both @ and the resource picker show App → services, while search directly finds children. The session saves concrete service keys, never an implicitly selected parent. Select-all captures current children; later additions remain unselected, renames preserve keys, and delete/recreate uses a new key. App-wide toolScope, grants and lifecycle remain independent: only selected children are resident; unselected global children can still be discovered. Verify sibling isolation and restored selections using the generated package.
