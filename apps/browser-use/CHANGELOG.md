# Changelog

## 0.1.7

- 整合本次应用更新并重新验证桌面平台发布。

## 0.1.6

- 新增 Linux AMD64 支持；由 Linux CI 执行检查、测试、构建、源码独立重建及 Backend 验证。

## 0.1.5

- 专用浏览器只在实际调用网页自动化工具时启动；启动 Moss、工具目录检查、打开设置、重新连接和重新启用 App 均不再弹出 Chrome。
- 关闭专用浏览器后，等下一次网页操作再恢复，继续复用原配置和登录状态。
- 增加真实 MCP 与 Host 启动回归，覆盖调用前不启动、并发首次调用与关闭后按需恢复。

## 0.1.4

- 自定义 Chrome 路径必须使用已存在且安装了 Playwright 扩展的用户配置，禁止通过不存在的目录创建空白系统 Chrome；配置文件环境变量也不能绕过启动保护。
- 专用浏览器退出后，原对话下次连接自动重新打开同一份配置。恢复只作用于建立连接，不重试已发出的网页操作。
- 清理旧默认配置遗留的浏览器路径与配置目录参数，兼容修复已迁移到 0.1.3 的设置。
- 增加启动拦截、同一 MCP 客户端恢复及持久化回归验证。

## 0.1.3

- 同时提供专用浏览器与日常 Chrome 两种模式，可在 App 内切换。
- 专用模式默认启用，使用独立应用身份的 Chrome for Testing，与用户日常 Chrome 分开运行。首次自动准备浏览器，无需安装扩展。
- 固定保留专用用户目录，重复和并发连接复用一个实例，关闭后重新打开仍保留网站登录状态。
- 保留日常 Chrome 扩展连接及高级 CDP 模式，不接管或关闭用户浏览器，不将系统 Chrome 用作专用模式的回退。

## 0.1.2

- 默认通过官方 Playwright 扩展连接日常 Chrome，使用已有标签页、登录状态和用户配置。
- 移除系统 Chrome 的自动化专用目录启动器，CDP 不可用时不再另开 Chrome。
- 升级时迁移旧的默认本机连接；保留用户明确选择的 CDP 连接及凭据。
- 连接设置提供日常 Chrome、已有 CDP、现有用户配置选择和扩展安装指引；区分工具就绪与实际浏览器连接。

## 0.1.0

- 从 MCP 管理抽取 Playwright MCP 为独立的网页操控 App，独立注册、配置和打包。
- 启用后自动启动或连接 Chrome 并检查连接，无需先打开页面。
- 提供浏览器状态、重连、连接设置与动态工具目录，支持明暗主题和窄窗口。
- 复用现有 MCP 工具调用与生命周期，不迁移旧配置。
