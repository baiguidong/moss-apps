# Changelog

## 0.1.4

- 适配 Host API 3：使用绑定当前 App 的 SDK，统一调用取消及错误处理。

## 0.1.3

- 修复查询知识库时，列表工具的顶层 `allOf` 导致模型接口返回 400 的问题。
- 工具参数使用标准对象定义，列出资料集时禁止传入 `collectionId` 的规则由后端校验，并在参数说明中明确。
- 构建与打包使用 SDK 统一检查工具输入 schema，在发布前报告不合规的工具定义。

## 0.1.2

- AI 写入仅接收资料集和明确的文件绝对路径；Agent 先整理文件，目录不再由 AI 写入工具扫描。
- 同一路径重新导入更新托管副本，内容未变跳过复制；移除 AI 原始正文新建/更新操作。
- 删除沿用 Host destructive/ask 权限策略和必填版本检查；增加完整权限链路与旧版本误删回归验证。

## 0.1.1

- AI 工具收敛为列表、搜索、读取、写入和删除 5 个；写入统一处理导入、新建和更新。
- 索引、任务和资料集管理保留为 App 内部 Action。
- 应用市场通过同域地址提供校验过的原始签名 ZIP，减少 GitHub 下载链路超时。

## 0.1.0

- 独立的本地知识库 App：资料集、文件与目录导入、文本编辑、全文检索和索引任务。
- 15 个标准 App 工具及文档资源提供者；默认全库查询，支持显式资料集筛选。
- 内置文档解析器与固定版本的 PDF 依赖；持久化后端、版本冲突保护和任务恢复。
- 新建数据目录，无原生知识库的历史迁移或兼容层。
