# 0.1.0 发布前审查

2026-09-30。逐项阅读 Backend 的文件操作、索引任务与恢复、SDK 的取消/关闭流程、前端状态更新、Manifest 契约，以及相邻 Moss Core 的删除差异和通用 Host/资源边界。

## 已修复

- 已有成功索引的文档再次编辑后，未完成任务曾在重启时被取消。现在关闭/崩溃后的未完成任务均恢复，主动取消的任务保留取消状态。
- 写入曾等待整个索引队列；删除无法及时取消自身任务。现在先停止同一来源的任务，再进行修改；不等待其他来源的解析。
- 文件读取和导出曾与写入并发，可能将旧版本号与新字节组合。现在文件操作共用串行通道，关闭先中止/收尾前台动作，再关闭数据库。导出按版本隔离，并校验复制内容哈希。
- 复制前计算的哈希可能与实际副本不一致。现在以临时副本哈希为准；重新索引验证托管文件实际字节，不信任旧配置哈希。
- 长中文标题可能超过文件名字节限制；不同特殊字符文件名可能被清洗成同名。现在按字节限制文件名，并添加稳定哈希保持唯一性，原始相对路径作为资源标识。
- 来源列表曾返回完整内部文件配置，可能超过 1 MiB RPC 限制。现在返回分页摘要；列表/导入结果/正文块有字节预算。Action 与 Tool 使用匹配的明确输出 Schema。
- 非文本文档保留旧索引时，阅读明确区分正文版本与当前文件版本，避免错误引用或无法删除。
- 前端的编辑/删除对话框固定操作目标和版本；继续阅读使用请求序号，避免旧请求覆盖新选择；被外部删除的资料集回到全库。
- PDF 测试曾依赖已生成的 dist。现在测试独立准备校验过的依赖；CI 显式使用 Node 22，干净检出也可先测试后构建。

## 验证

- Node 22：36 项测试，包含检索质量、实际 PDF/Office 解析、CRUD、隔离、取消、恢复、并发版本保护、导出和文件名冲突。
- TypeScript、Manifest、构建、ZIP 打包。
- 实际 ZIP 安装到临时 Core Runtime：15 个工具、参数/结果契约、默认全库与显式筛选、拒绝 projectId、资源解析、持久化、并发更新冲突、启停撤销工具。
- 实际 Core EmbeddedAppView + preload + Backend：资料集创建、编辑、目录导入、搜索、阅读、打开副本、取消/确认删除和任务列表；浅色、深色、800px 布局；无 renderer error。
- Core 原生注册/设置/UI/项目耦合清理差异已审查；Core 987 项桌面测试及类型/构建检查通过。Server 的既有 boundary 测试失败已用原始 HEAD 复现，与迁移无关。

桌面证据位于 `artifacts/moss.library/verification/0.1.0/`。原生选择/打开文件使用确定性测试响应，其余链路真实执行；不访问现有用户知识库数据。执行平台为 macOS，未执行 Windows 实机验证。首次版本不提供数据迁移、旧接口兼容、OCR、旧 Office 格式或加密 PDF 解析。

## 0.1.1 增量审查

根据使用反馈，AI 工具从 15 个收敛为 `list/search/read/write/delete` 五个。写入工具的 import/create/update 使用互斥输入契约，更新与删除要求非空版本号；只读工具不分发写入或管理动作。页面内部管理 Action 保持可用。

新增 3 项工具注册、路由与输入边界测试，App 共 39 项测试通过；实际桌面安装验证只注册 5 个工具，覆盖统一写入的新建、更新、导入及删除。新增 2 项市场分发测试，验证 ZIP 字节与签名元信息不变，校验和错误、截断、超长、未签名及非法路径均拒绝发布。

市场通过同域托管签名包，GitHub Release 仍保存不可变的原始文件；镜像构建前严格校验大小和 SHA-256，发布和手动目录更新共用相同配置并串行部署。
