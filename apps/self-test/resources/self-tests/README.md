# Moss AI 自测清单

编辑本目录的 `catalog.json` 即可配置发布版本的测试项。自测 App 安装包包含整个目录，运行时从随包资源读取，不依赖开发机器的仓库。

每项包含稳定的 `id`、`title`、是否默认选中的 `default`、是否涉及模型调用的 `requiresModel`、`prerequisites`、`steps` 和逐条验收的 `expected`。ID 只能使用小写字母、数字及连字符。

文本中的 `{{runId}}`、`{{runShortId}}` 会在开始时替换为本轮完整编号、前八位编号，并保存到本轮报告。用于新建会话、工作流和团队名称，确保复用实例时不会误用上轮同名数据。

默认八项包含真实模型收发消息、两个真实会话的切换、启动、主题、继承的应用列表、文件预览，以及工作流和 Agent Team 的真实演示任务。停止生成、模型选择另行勾选。控制端和被测实例均使用主 Moss 的真实文本模型及完全放行权限；`requiresModel` 标记哪些项目涉及被测实例的模型调用。新会话必须发送首条消息才会进入侧栏，草稿不算已创建会话。

固定测试实例首次继承当前设置、App 版本、启用状态、授权与配置，以及个人技能和助手；后续复用环境，测试完成后保留窗口和数据。可随时打开、主动同步环境或清理测试数据。依赖业务数据的扩展用例应明确写出前置条件，未满足时标记 blocked。准备期间显示复制进度；结束后自动打开包含问题线索、复现步骤和内嵌截图的 HTML 报告。

每轮保存清单及 revision，测试会话通过本 App 自带的 Playwright MCP 操作独立 Electron 实例，逐项提交实际观察及截图。每个 expected 都有检查结果且截图存在才允许标记 passed。尚未执行为 pending；模型结束该项却未提交结果时标记 blocked，整轮不能算通过。

新增用例后运行 `bun run test`（在 apps/self-test 目录），打包检查会验证清单格式。不要在测试清单中保存凭据或个人数据。
