# TAKT 工作流

独立的 Moss App，与现有「工作流」并存。通过 Moss 对话创建、编辑和运行 TAKT 工作流，在 App 中查看定义图、实际执行、节点结果和运行历史。TAKT 版本固定为 0.70.0。

## 0.2.0

包含对话创建/修改入口、会话资源选择、工作流搜索与分页、修订历史及另存修订、复制、归档/恢复、YAML 导入/导出和完整事件记录。在运行中可暂停后续模型调用、继续，以及向后续步骤补充要求。暂停等待在途调用完成，仍消耗同一个 Moss task 的总时长；不回滚已经发生的工具操作。

支持内联 Agent 步骤、条件转移、有限循环、静态并行、不可变修订、后台运行、取消、重跑、历史和大结果分块读取。模型、工具与权限由 Moss 来源会话决定。

点击「新建工作流」或「从一句话开始」会打开 Moss 自然语言草稿。描述需求并发送后生成工作流，保存前后都不会自动运行。已有工作流的「编辑」按钮提供 YAML 编辑器，也可以通过「对话修改」继续完善。导入 YAML 是独立入口。

在 Moss 会话选择本 App，然后说：「创建一个分析需求、审查、汇总的工作流」「用这个工作流分析一个本地笔记 App 的 MVP」「查看刚才的运行结果」。生成并运行需由用户明确要求；单纯保存和查看不会触发执行。

通过对话或 YAML 编辑结构，图用于查看。暂不支持文件型 facet、子工作流、command/system 步骤、定时触发、拖线编辑和跨进程断点恢复。关闭页面不停止运行；关闭 Moss 或重启 Backend 后，进行中或暂停的任务标为中断。重跑创建新 run，不自动重放中断步骤。运行总时长最多 30 分钟、Agent 调用 128 次、并发 4、token 50 万；每个定义还必须配置 1–64 的 max_steps。

## 会话工作台（0.3）

在配套更新的 Moss 中，当前会话引用的工作流会出现在顶部「工作流」入口。点击在会话正文内展示定义或实际运行图，底部保留同一个输入框；发送消息后返回聊天。收起并重开工作台保留图状态，切换会话只显示对应记录。

「在会话中讨论此节点」准备带有固定修订、runId、nodeId 和 occurrenceId 的未发送引用。运行按钮准备当前会话草稿，实际发送才会执行；图内可暂停、继续、停止和查看完整事件。App 独立窗口仍提供目录、修订与完整管理。

Manifest 的普通 view `moss-conversation` 声明工作台入口，Moss 通过 `target` 参数传入 App 自己的资源 route。不需要增加模型配置或执行服务；旧 Moss 仍可打开完整 App，新顶部入口需要本次 Moss 会话 UI 更新。

`node scripts/verify-conversation.mjs` 操作运行中的开发版 Moss，验证自然语言新建、定义修订预览、节点引用、同会话运行和暂停/继续，使用真实模型并保留测试记录。只在用户授权实测后运行；失败后可用 `TAKT_RESUME=1` 继续同一组测试。

## 外观（0.3.4）

外观跟随 Moss「设置 → 外观 → 背景样式」，支持默认、网格、圆点、渐变和「TAKT 苔绿」。明暗模式和跟随系统同样沿用 Moss 设置，独立 App 与会话内 graph 同步生效，无需刷新。选择 TAKT 苔绿即可使用原 0.3.3 的柔和绿色风格；其他预设与 Moss 的标准配色保持一致。

## 开发

工作区安装依赖后运行 `bun run check`、`bun run test`、`bun run build`。`bun run test:host` 需要相邻 Moss Core 仓库，运行真实 App Runtime / Tasks / Execution IPC 集成；使用受控模型返回值，不代表真实模型测试。桌面实测与截图单独保存到 artifacts。

`scripts/engine-build.mjs` 在构建时为固定 TAKT 版本替换 Agent runner / Provider registry 入口，并调整资源定位和 Git 提示，明确 App 不自动提交或推送。流程调度、规则判断和并行引擎保留上游实现；每次 Agent 执行（包括内部状态判断）都请求 Moss Host。只在 App 私有目录保存运行记录，不要求全局 CLI 或独立平台。

依赖由安装包带入；源码和锁文件随 ZIP 交付。首次重建需要按锁文件下载构建依赖。TAKT MIT 许可位于 `dist/backend/takt-resources/LICENSE`，来源为 https://github.com/nrslib/takt。
