# Changelog

## 0.4.2 - 2026-09-23

- 按 Desktop 与 Server target 分别声明 Host 协议，并要求支持该 Manifest 契约的 Host API 2.1。

## 0.4.1 - 2026-09-22

- 同步 Host API 2 的初始化协议：连接状态可以在 `service.ready` 前上报，初始化期间的 Binding 事件可以完成 ACK，不再循环等待至握手超时。
- 同步新的 Action principal、Host 请求超时、Account 事件、Remote owner 和 Desktop 分块文件类型定义。

## 0.4.0 - 2026-09-22

- 升级到 Host API 2，删除旧 `moss.channel/v1` 适配与兼容映射。
- 收消息、Turn 结果和投递确认直接使用 `moss.agent/v1` 标准字段。
- 飞书 SDK、配对、事件去重和消息发送继续完全由 App 持有，Core 不包含飞书定制逻辑。
- 配置 schema 只接受当前字段，不迁移未发布版本的历史配置。

## 0.3.0

- 飞书配置、配对状态和运行状态全部由独立 App 管理，不再依赖 Moss 中的飞书专用 IPC 或 Adapter 进程。
- 同一个 App Backend 现在可由 Desktop 或 Moss Server 的通用 App Runtime 托管。
- 移除旧独立进程启动模式，统一使用 Node.js App Backend 协议。

## 0.2.1

- 允许保留新版不识别的历史配置字段，避免升级因旧配置校验失败，并确保回滚后原配置仍可使用。

## 0.2.0

- 飞书私聊保持 AI 自动回复和固定会话，不引入人工接管、草稿审核或成员回复策略。
- Moss Host 在执行层强制使用自动回复和固定会话；打开设置时同时清理试用阶段遗留配置。
- 增加工具、技能、连接器白名单和工具确认策略，由 Moss Core 在执行层强制限制。
- 移除卡片回复、会话中心、新建/切换/停止会话、手机端审批、主动通知和附件资源处理。
- Server 托管路径同步移除会话控制和手机端权限卡片，并拒绝需要交互确认的工具操作。
- 飞书开放平台只需 3 项消息权限，并且只订阅私聊消息事件。
- 要求 Moss Host API 1.2，并增加消息输入校验、幂等投递和敏感 Turn 数据脱敏。
- 修复资源“不额外限制”的保存语义、解绑白名单与状态刷新竞态。

## 0.1.3

- 飞书设置页改用 Moss 桌面端统一的颜色、表面、控件和状态样式。
- 移除与宿主标题重复的 App 品牌区，调整为紧凑的设置分组布局。
- 完整跟随 Moss 的浅色、深色与背景样式，并在外观变化时动态同步。

## 0.1.2

- 将飞书配置集中到 App 设置页。
- 增加完整配置说明、配对管理和密钥掩码。
- 修复保存配置后 App 页面与 Desktop 状态不同步的问题。
- 管理页仅保留运行控制和日志，不再重复展示业务配置。
